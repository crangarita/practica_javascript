# Actividad 3: CRUD real con JavaScript, Fetch y Supabase

## Proyecto: Gestión de estudiantes conectada a PostgreSQL

## Objetivo general

Reemplazar el almacenamiento en `localStorage` por una base de datos real utilizando **Supabase**, su API REST y JavaScript con `fetch()`.

La evolución será:

```text
Actividad 2
HTML + CSS + JavaScript
        ↓
Array
        ↓
localStorage
```

Ahora:

```text
Actividad 3
HTML + CSS + JavaScript
        ↓
fetch()
        ↓
HTTP / REST
        ↓
Supabase
        ↓
PostgreSQL
```

# 8. Nuestro primer GET

```javascript
async function obtenerEstudiantes() {

    try {

        const respuesta = await fetch(
            `${SUPABASE_URL}/rest/v1/estudiantes?select=*`,
            {
                method: "GET",
                headers: obtenerHeaders()
            }
        );

        if (!respuesta.ok) {
            throw new Error(
                "No fue posible consultar estudiantes"
            );
        }

        const estudiantes =
            await respuesta.json();

        console.log(estudiantes);

        mostrarEstudiantes(estudiantes);

    } catch (error) {

        console.error(
            "Error:",
            error
        );
    }
}
```

Ejecutar:

```javascript
obtenerEstudiantes();
```

# 11. CREATE con POST

Antes hacíamos:

```javascript
estudiantes.push(estudiante);
```

Ahora:

```javascript
async function crearEstudiante(estudiante) {

    const respuesta = await fetch(
        `${SUPABASE_URL}/rest/v1/estudiantes`,
        {
            method: "POST",
            headers: obtenerHeaders(),
            body: JSON.stringify(estudiante)
        }
    );

    if (!respuesta.ok) {
        throw new Error(
            "No fue posible crear el estudiante"
        );
    }
}
```

Uso:

```javascript
const estudiante = {
    nombre: document.querySelector("#nombre").value,
    correo: document.querySelector("#correo").value,
    programa: document.querySelector("#programa").value,
    estado: "Activo"
};

await crearEstudiante(estudiante);
await obtenerEstudiantes();
```

Flujo:

```text
Objeto JavaScript
       ↓
JSON.stringify()
       ↓
JSON
       ↓
POST
       ↓
Supabase REST
       ↓
PostgreSQL
```

# 12. DELETE

```javascript
async function eliminarEstudiante(id) {

    const confirmar = confirm(
        "¿Desea eliminar este estudiante?"
    );

    if (!confirmar) {
        return;
    }

    const respuesta = await fetch(
        `${SUPABASE_URL}/rest/v1/estudiantes?id=eq.${id}`,
        {
            method: "DELETE",
            headers: obtenerHeaders()
        }
    );

    if (!respuesta.ok) {
        throw new Error(
            "No fue posible eliminar"
        );
    }

    await obtenerEstudiantes();
}
```

# 13. UPDATE con PATCH

```javascript
async function actualizarEstudiante(
    id,
    estudiante
) {

    const respuesta = await fetch(
        `${SUPABASE_URL}/rest/v1/estudiantes?id=eq.${id}`,
        {
            method: "PATCH",
            headers: obtenerHeaders(),
            body: JSON.stringify(estudiante)
        }
    );

    if (!respuesta.ok) {
        throw new Error(
            "No fue posible actualizar"
        );
    }

    await obtenerEstudiantes();
}
```

# 18. Seguridad

Una **Publishable Key** está diseñada para aplicaciones cliente y puede estar presente en el frontend.

Pero eso no significa que debamos dejar la base de datos sin protección.

La seguridad debe apoyarse en:

```text
Permisos
+
Row Level Security (RLS)
+
Autenticación
```

Nunca debemos colocar una **Secret Key** en:

```text
HTML
JavaScript del navegador
Repositorio frontend público
```
